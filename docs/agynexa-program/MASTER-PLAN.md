1. **HERO FREEZE:** حافظ حرفيًا على الشاشة الافتتاحية الحالية وفيديو `public/videos/background.mp4` ومكونات `landing-5-hero-video.tsx` و`landing-5-hero-section.tsx` وما يؤثر عليهما من CSS والتشغيل والمقاسات والطبقات والحركة والنصوص. لا تعيد تصميمها. خذ baseline وبصمات SHA-256 قبل التعديل؛ تحقق من ثباتها إذا مسّ التغيير أنماطًا مشتركة أو عند التسليم النهائي. يسمح بإعادة بناء الأقسام الواقعة بعدها وجميع الصفحات الداخلية.
2. **DESIGN SYSTEM LOCK:** الهوية المرجعية هي **القالب الحالي**، لا ألوان Kore.ai. استخرج tokens من المشروع نفسه وألزم كل الصفحات الجديدة والقديمة بنفس الأسود/الداكن والأخضر الزمردي والخطوط والـspacing والـradius والحدود والأيقونات والـgrid والـresponsive. استخدم مكونات الأزرار والبطاقات والحقول والقوائم والحوارات الحالية؛ اضبط حالات hover/focus/disabled وRTL/LTR. لا تُدخل theme أو UI kit بديلًا أو ألوانًا عشوائية أو gradients مختلفة. وثّق القيم الفعلية ولا تخمّن Hex. التغييرات في CSS العالمي ممنوعة إن أثّرت على الـHero.
3. **ISOLATION:** اعمل على نسخة أو فرع منفصل مثبت المصدر. لا تعدّل Production أو المستودع الأساسي أو نطاقه أو Secrets أو مشروع Supabase قائم، ولا تدفع أو تنشر إنتاجيًا. المعاينات تكون Vercel Preview فقط عند إمكانها، دون تجاوز SSO أو تغيير الحماية. إذا تعذر رابط Preview أعطني رابط localhost ولقطات صادقة.
4. **INTELLECTUAL PROPERTY:** افحص Kore.ai والوثائق والأصول العامة المصرح بها لفهم تصنيف الخدمات، الوظائف، Business Logic العام، تدفقات المستخدم، التكاملات والتقنيات والعرض البصري. لا تنقل نصوصًا محمية أو تصميمات مميزة أو صورًا أو شعارات أو عملاء أو شهادات أو دراسات حالة أو كودًا خاصًا؛ ولا تكتف بإعادة تسمية نسخها. اكتب مادة أصلية متعمقة واصنع رسومات أصلية متوافقة مع ترخيص الاستخدام التجاري. استخدم REA قراءةً وتحليلًا للمواد العامة فقط، دون دخول غير مصرح أو تجاوز حماية أو استدعاء APIs خاصة أو تغييرات في أنظمة الغير.
5. **HONEST POSITIONING:** نقدم AGYNEXA باعتبارها جهة **تصمّم وتطوّر وتنفّذ حلول وكلاء الذكاء الاصطناعي للمؤسسات**. لا تضع في الموقع العام لغة «نتعلم» أو «نسخة تجريبية» أو «تجربة محلية»؛ ولا تدّع منتجات جاهزة أو عقودًا أو أرقام نتائج أو تكاملات مؤهلة أو شهادات أمان غير مثبتة. في الوثائق الداخلية ميّز `IMPLEMENTED / SPECIFIED / REQUIRES_ACCESS / BLOCKED`، واكتب عرض الخدمة عامًا بدقة مثل «نصمم وننفذ بحسب نطاق المشروع».
6. **APPROVED CONTENT:** اقرأ أولًا محتوى المشروع الحالي والنسخة الأصلية والتسليمات السابقة. لا تهدم المحتوى المقبول أو الخدمات القائمة، وخصوصًا المعرفة المؤسسية والمشتريات والمستحقات/التحصيل وعمليات العملاء. استوعبها في التصنيف الجديد. اكتب عربيًا وإنجليزيًا طبيعيين ومتكافئين معنًى. استخدم Humanizer فقط إن ثبت توفره وأمانه في بيئة Codex وبلا تغيير المعنى؛ وإلا حرر يدويًا لإزالة الحشو والعبارات النمطية.
7. **TOOLS & SKILLS:** جرد الأدوات والمهارات المتصلة **داخل بيئتك** ولا تفترض اتصالًا لم يُختبر. استخدم REA للبحث المصرح، وBetter Design لمراجعة التصميم/الرسومات، وFigma إن كان متصلًا، وأداة توليد صور مرخّصة عند اللزوم. ابحث عن مهارة `Andrej Karpathy Skills` أو `karpathy-guidelines` وتحقق من المصدر والتعليمات قبل تشغيلها؛ استخدم مبادئ فهم الكود أولًا، البساطة، أقل تغيير لازم، وتجنب الإفراط في الهندسة. لا تُثبّت أدوات جديدة ولا تنفق أرصدة مدفوعة دون إذن.

## المرحلة 2: خدمات AGYNEXA ومحتواها وخريطة الصفحات

أنشئ مصفوفة دقيقة: مفهوم Kore.ai العام ← وظيفة قابلة للبناء ← عرض AGYNEXA مستقل ← inputs/steps/tools/permissions/outputs/metrics/integration needs ← ما هو موجود في المشروع وما يحتاج تطويرًا. الأسماء التالية اقتراحات تحتاج فحص توافرها التجاري، وتظل خدماتنا القديمة محفوظة:

- `ServiceFlow`: خدمة العملاء، الطلبات، التصعيد والقنوات.
- `WorkOps`: إجراءات الموظفين وHR وIT والمساعدة الداخلية.
- `ProcessOps`: المشتريات، الفواتير، التحصيل والعمليات المتسلسلة.
- `KnowledgeGrid`: المعرفة الداخلية وRAG والاستشهاد والصلاحيات.
- `AgentFabric`: تنسيق الوكلاء المتخصصين وتوزيع المهام.
- `ConnectLayer`: التكاملات والبيانات وREST/SOAP/MCP.
- `VoiceBridge`: وكلاء الصوت والقنوات الهاتفية المرخصة.
- `AgentAssist`: مساعدة موظفي الدعم والملخصات ومسودات الرد.
- `ControlPlane`: الأدوار والحوكمة والموافقات وسجل التدقيق.
- `InsightLoop`: مراقبة التنفيذ وتقييم الجودة والتحليلات.

اكتب لكل خدمة محتوى عربيًا وإنجليزيًا أصيلًا وغنيًا: لمن الخدمة، الألم التجاري، ما نقدمه، خطوات العمل، المعمارية العامة، الأنظمة الممكن ربطها، مخرجات المشروع، ضوابط التشغيل، القطاعات المناسبة، FAQ، CTA، وبيانات SEO. أنشئ صفحات `services/solutions`, صفحات الخدمات المنفصلة، `industries`, `integrations`, `architecture`, `security`, `methodology`, `resources`, `about`, و`start/contact` بحسب Router القائم. «من نحن»: المهندس أدهم يونس، المؤسس والرئيس التنفيذي بحسب توجيه المالك، من دون سيرة أو إنجازات مؤلفة. حافظ على النص السابق المقبول حيث يلائم العمل. تسليم: `service-mapping.csv`، sitemap، المحتوى والمكوّنات الأولية أو معاينة غير إنتاجية؛ **توقف**.

## المرحلة 3: المعمارية وقواعد البيانات والـAPIs والتكاملات

من الوثائق العامة لـKore.ai فقط استخلص الأنماط: tool calls، synchronous/asynchronous runs، REST/SOAP، MCP، OAuth، مصادر المعرفة، قنوات الصوت والمراسلة، سجلات التنفيذ، والحماية والتصعيد. **لا تنقل API خاصًا بالشركة ولا تخترع أن نقاطه متاحة لنا**.

قيّم خيارات ربط المؤسسات بناءً على وثائق كل مزود، مثل Salesforce/HubSpot/Dynamics/Zoho؛ Zendesk/ServiceNow/Jira/Freshdesk؛ Microsoft Graph/Teams/SharePoint وGoogle Workspace وSlack؛ SAP/Odoo/ERPNext؛ WhatsApp Business/Twilio؛ ومخازن PostgreSQL/pgvector حيث يلزم. لكل مزود: الرابط الرسمي، OAuth scopes أو API-key، الكائنات، endpoints المؤكدة، Webhook signature، الحدود، التكلفة، المزامنة، الخصوصية والأخطاء. المسارات غير المتحققة = `TO_VERIFY`، وليست «جاهزة».

اقترح **عقود AGYNEXA الخاصة** عبر OpenAPI 3.1 وZod، على سبيل المثال (لا تفترض تنفيذها):
`GET /api/v1/catalog/services`؛ `POST /api/v1/project-briefs`؛ `GET /api/v1/integrations`؛ `POST /api/v1/connectors/:provider/connect`؛ `GET /api/v1/connectors/:provider/callback`؛ `POST /api/v1/knowledge/search`؛ `POST /api/v1/agents/:id/runs`؛ `GET /api/v1/runs/:runId`؛ `POST /api/v1/approvals/:id/decision`؛ `POST /api/v1/webhooks/:provider`؛ `GET /api/v1/observability/runs`. راجع تعارضات Router القائم، وافصل العام والإداري والداخلي. حدد auth، tenant isolation، schema، status/errors، rate limit، idempotency، OAuth state/PKCE، توقيع webhooks، والتدقيق.

اقترح مخطط PostgreSQL/Supabase مع ERD وRLS وعزل مستأجرين: `organizations`, `memberships`, `service_catalog`, `project_briefs`, `connector_accounts`, `connector_sync_jobs`, `knowledge_sources`, `documents`, `document_chunks`, `agents`, `workflows`, `agent_runs`, `tool_invocations`, `approvals`, `audit_events`, `webhook_events`, `feedback`. المهاجرات تُجهز للفحص فقط، **ولا تُنفّذ على قاعدة متصلة أو قائمة**. التسليم: `architecture/openapi.yaml`، `integration-matrix.csv`، `data-model.md`، `threat-model.md`، `workflow-contracts.md`؛ **توقف**.
