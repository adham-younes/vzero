# استكمال المرحلة 5 — الحسابات وموجزات المشاريع

## النطاق والقرار

المالك فوّض إنشاء قاعدة البيانات والتسجيل والدخول الفوري دون بريد تأكيد في مشروع xsyxvswbiptbyxyqhdim عبر حساب agynexa. هذا استكمال AUTH-01 / DATA-01 / LEAD-01، لا بدء مراحل بديلة. قورنت مراجعة السوق كاملة بالكود: الموقع والمحتوى والاتصال منفذة؛ الحسابات والحفظ لم تكن منفذة. نطبق نصيحتها ببناء الكيانات اللازمة فقط وعزل المستخدمين واختبار الإخفاق والتكرار، دون تحويل الهوية إلى RFQ أو تنفيذ مسودة الـ20 جدولًا. تبقى المؤسسات والعضويات وتشغيل المعرفة والنماذج خارج هذا التسليم.

## ما تغير

- تسجيل/دخول/خروج عربي وإنجليزي وصفحة حساب (ستة URLs noindex خارج sitemap التسويقي ذي 64 عنوانًا).
- إنشاء الحساب من الخادم عبر Auth admin.createUser مع email_confirm=true ثم دخول بكلمة المرور، دون signUp أو invite أو رسالة تأكيد. إعداد تأكيد البريد العام في Supabase لم يتغير؛ هذه سياسة مسار التطبيق فقط. لا إثبات ملكية بريد ولا عضويات تلقائية بحسب نطاقه. المفاتيح السرية خادمية فقط.
- جلسة HttpOnly/Secure في الإنتاج وSameSite=Lax. واجهات الحساب تقرأ getUser وتكتب تجديد الجلسة عبر @supabase/ssr؛ الصفحات التسويقية لا تقرأ جلسات. الردود الشخصية private/no-store.
- profiles وproject_briefs مع RLS وملكية UUID صريحة. دالة private تتحقق من بقاء session_id في Auth؛ بعد إبطال الجلسة ترفض البيانات حتى لو بقي JWT غير منتهٍ. لا صلاحية لتعديل المالك أو أدوار من user_metadata.
- الموجز يراجع ويحتاج موافقة صريحة ثم يحفظ. إعادة نفس request_key تعيد السجل، واختلاف المحتوى مع نفس المفتاح ينتج 409. عرض آخر 100 موجز وحذف بموافقة المستخدم. سقف 20 موجزًا لكل مستخدم خلال 24 ساعة في قاعدة البيانات. التنزيل ومسودة البريد اليدوية محفوظان.
- التسجيل والدخول لهما حدود ثابتة كل ساعة عبر مخزن خاص: تسجيل 10/IP و5/بريد و100 إجمالي، دخول 40/IP و20/بريد، مع حدود Supabase الإضافية. المخزن يحفظ HMAC لا البريد أو IP الخام؛ التنظيف بعد ساعتين عند الاستخدام التالي. رفض المصدر المختلف، JSON فقط، حجم 20KB وحدود حقول.
- فحص Advisors كشف صلاحيات EXECUTE زائدة لدالة event trigger موجودة من المنصة؛ أزيل وصول العملاء فقط، وبقي trigger تفعيل RLS قائمًا. الملاحظة INFO المتبقية تخص جدول المحددات الخاص الذي يمنع جميع أدوار العملاء عمدًا.

## التنفيذ والأدلة

ملفات التطبيق: lib/supabase/server.ts، lib/account-validation.ts، @components/account-ui.tsx، @components/project-brief.tsx، app/api/auth/* وapp/api/account وapp/api/v1/project-briefs. حُزمت @supabase/supabase-js@2.118.0 و@supabase/ssr@0.12.7 بإصدارات مثبتة؛ لا تحديث لبقية التبعيات. ملفات SQL التنفيذية في supabase/migrations، وفحص الصلاحيات في supabase/tests/accounts_rls.sql. مسودة schema-review.sql محفوظة دون تنفيذ.

الاختبارات: 10 وحدات نجحت؛ build/TypeScript نجح. معاملة اختبار SQL ببيانات مصطنعة ثم ROLLBACK أثبتت وصول المالك ومنع القراءة/الكتابة/الحذف عبر المستخدمين ومنع الزائر وإبطال الجلسة وحدود المحاولات. اختبار الواجهة والنشر والتسجيل الحقيقي يسجل في [الدليل](../evidence/accounts-2026-10-20/verification.json) بعد التحقق. لا ادعاء نجاح إنتاج قبل ذلك.

## الحدود والاستئناف

لا مؤسسات مشتركة أو دعوات أو مدير عام داخل التطبيق أو تغيير بريد/استرجاع كلمة مرور أو MFA أو CRM/إشعارات أو تشغيل AI/RAG. المالك يستطيع مراجعة الموجزات بصلاحيته الإدارية في Supabase؛ لا بريد تلقائي للتنبيه. لا سياسة احتفاظ تلقائي ببيانات المستخدمين مفترضة؛ حذف الموجز متاح، والنسخ الاحتياطية/استعادة قاعدة كاملة لم تختبر ولا يُدعى ضمانها. قدرة rate limiting ليست حماية شاملة من هجوم موزع. يُعتمد نطاق الاسترجاع/المؤسسات والنموذج وميزانية التشغيل قبل امتدادها.

التراجع: أوقف مسار التسجيل/الحفظ أو ارجع لكود الإصدار السابق، واحتفظ بالجداول وبياناتها؛ لا DROP ولا rollback مدمر بعد استقبال بيانات فعلية. عند إعادة اعتماد تأكيد البريد مستقبلًا، غيّر مسار التسجيل قبل فتح العضويات أو الربط بعنوان البريد.

مراجع التنفيذ: [SSR](https://supabase.com/docs/guides/auth/server-side/creating-a-client)، [إنشاء حساب خادمي](https://supabase.com/docs/reference/javascript/auth-admin-createuser)، [تغييرات Data API](https://supabase.com/changelog/45329-breaking-change-tables-not-exposed-to-data-and-graphql-api-automatically)، [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).

ملفات migrations أُنشئت عبر CLI ثم طُبقت عبر MCP؛ طابقت أرقام ملفاتها بإصداري السجل الفعلي العائدين من list_migrations: `20261020074037` و`20261020074207`، لتجنب محاولة تطبيقها مجددًا من CLI.
