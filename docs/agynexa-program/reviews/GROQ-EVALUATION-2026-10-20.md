الأسعار أعلاه للمعالجة العادية المعلنة، لا إجمالي تكلفة RAG أو تشغيل الأدوات أو التخزين. [خطة Developer](https://console.groq.com/docs/billing-faqs) فوترة بحسب الاستخدام؛ ليست حصة اشتراك غير محدودة. [120B](https://console.groq.com/docs/model/openai/gpt-oss-120b) و[20B](https://console.groq.com/docs/model/openai/gpt-oss-20b) لهما سياق 131072. قائمة النماذج تعرض حدود Developer أساسًا 1000 طلب/دقيقة و250K token/دقيقة لكل منهما؛ [الحدود الفعلية](https://console.groq.com/docs/rate-limits) قد تختلف حسب المؤسسة والمشروع، ولم نفحص حساب المالك.

## تعدد النماذج والمفاتيح

مفتاح واحد يمكنه استدعاء النماذج المسموحة للمشروع عبر حقل model. أكثر من مفتاح مفيد لفصل Production/Preview/Development، والإبطال والتدوير ومراقبة الإنفاق، ولا يلزم مفتاح لكل نموذج. [Projects](https://console.groq.com/docs/projects) تدعم مفاتيح وحدودًا لكل مشروع تحت سقف المؤسسة؛ إنشاء مفاتيح أو مشاريع إضافية لا يرفع سقفها. لا key rotation لتجاوز 429 أو سقف الإنفاق.

التركيب المقترح: GROQ_API_KEY خادمي في Vercel لكل بيئة بقيمة مناسبة لها؛ إعدادات مقترحة GROQ_MODEL_PRIMARY وGROQ_MODEL_FAST تحدد النموذجين. هذه أسماء تصميم وليست متغيرات يقرأها الكود الحالي. لا NEXT_PUBLIC للمفاتيح. توجيه حتمي حسب نوع المهمة، وحدود tokens/مهلة/تزامن، وتسجيل usage والنموذج والتكلفة دون نصوص مستندات. retries محدودة تراعي Retry-After؛ منع تكرار أفعال الأدوات. إضافة مزود آخر لاحقًا تمنح استقلالًا أكبر من تعطل Groq مقارنة بمفتاح ثانٍ لدى نفس المزود، بشرط اعتماد إرسال البيانات إليه.

[Spend Limits](https://console.groq.com/docs/spend-limits) تشمل مفاتيح المؤسسة كلها، وتحديث القياس قد يتأخر 10–15 دقيقة؛ يلزم سقف تطبيق احترازي وحصص للمستخدمين، ولا ضمان لسقف نقدي لحظي. لا ميزانية ولا تغيير فاتورة نفّذ في هذا التقييم.

## طبقة المعرفة وما يلزم قبل التنفيذ

Groq لتوليد الإجابة لا ينشئ تلقائيًا استرجاعًا بمصادر وصلاحيات. يظل تقسيم المستندات والاسترجاع وعزل البيانات وإبطال المستندات في نطاق RAG-01. نموذج embeddings واختبار العربية ما زالا غير محسومين؛ لم يظهر نموذج embedding في القائمة العامة التي راجعناها، بينما يحتوي [SDK Groq الرسمي](https://github.com/groq/groq-python/blob/main/examples/embedding.py) على مثال embeddings. وجود SDK لا يثبت إتاحة نموذج لحساب المالك أو ملاءمته للعربية؛ تحقق من الحساب/endpoint قبل الاعتماد أو اختر مزودًا منفصلًا بعد تقييمه. لا إعلان أن Groq لا تدعم embeddings مطلقًا.

قبل التشغيل: إضافة المفتاح خادميًا دون كشفه، التحقق من /models والصلاحيات والحدود، اعتماد حد إنفاق، ثم اختبار بيانات عامة مأذون بها وتحديد embedding. [سياسة بيانات Groq](https://console.groq.com/docs/your-data) تميز inference العادي عن ميزات تحتفظ بالحالة واستثناءات الموثوقية/إساءة الاستخدام؛ راجع Data Controls قبل مستندات عملاء فعلية. لا تغيير في الموقع أو قاعدة البيانات ضمن هذا التقرير.
