# برنامج Agent Studio

امتداد للموقع القائم وفق [تكليف المالك](EXECUTION-PLAN.md)، ثم [D24](../DECISIONS.md) الذي فوّض متابعة B وإصلاح الحساب وإزالة مصادر الأصول من الواجهة. يحفظ برنامج الموقع 0–6 ومراجعة السوق دون تبنّي تحويل RFQ.

| المرحلة | النطاق | الحالة |
|---|---|---|
| A | توثيق وتصحيح CSS للمقدمة مع حفظ الملفات | متحققة محليًا؛ أذن المالك بالمتابعة دون إعادة تعديلها |
| B | حسابات بلا بريد ومساحة مالك واحد وقالبان ووكلاء محفوظون | **VERIFIED_LOCAL**؛ [التسليم والأدلة](STAGE-B.md)، غير مفعّلة في الإنتاج |
| C | Groq واسترجاع واستشهادات وتقييم النموذجين | NOT_STARTED، بعد قبول B |
| D | طلب دعم بموافقة وإصدارات وAPI ثم widget بعد قبول API | NOT_STARTED، بعد قبول C |
| E | تسليم واختبارات واستعداد تجاري | NOT_STARTED، الإنتاج بتفويض مستقل |

الفرع `codex/agynexa-studio-stage-a` و[PR #18](https://github.com/adham-younes/vzero/pull/18). لا main أو دمج أو Production، ولا تغيير مشروع Adham-AI-Agent- أو agynexa.si. SQL Studio مطبق محليًا فقط؛ القاعدة المستضافة وإعدادات Auth تحتاج تفويضًا مستقلًا يحدد المشروع والإجراء. مهاجرتا الحسابات السابقتان مطبقتان في الإنتاج ولا تعادان.

التسجيل والدخول بلا بريد؛ التأكيد الإداري لا يثبت ملكية البريد. الصلاحيات بالعضوية وuser_id، بلا OAuth أو SMTP أو استعادة مصطنعة. استعادة الحساب عائق إطلاق تجاري، ولا تعطل الاختبار الداخلي المعزول.

Groq المدفوع مفوض لمرحلة C. لم يستدعَ في A أو B. اختيار GPT-OSS/Qwen محفوظ ضمن المسودة دون ادعاء التوافر؛ Qwen للتقييم الداخلي. لا embeddings مفترضة، ويمكن البدء بـPostgreSQL lexical RAG وفق التكليف.

[تقرير A التاريخي](STAGE-A.md) و[تقرير B الجاري](STAGE-B.md). لا Runtime أو معرفة أو نشر أو widget بعد. AgentNexOS يبقى صفحة تعريفية؛ Studio مسار إضافي خاص بلا فهرسة أو تخزين مشترك.

التوجيه الأحدث D-26 اعتمد إكمال البرنامج والنشر. [تسليم C/D/E](STAGES-CDE.md) يستبدل تعليمات التوقف السابقة للحالة الجارية.
