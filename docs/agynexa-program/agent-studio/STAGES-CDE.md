# Studio C/D/E: المعرفة والتشغيل والنشر

20 أكتوبر 2026. التفويض D-26: إكمال المراحل ثم نشر إنتاجي على vzero. هذا التقرير يُحدّث بنتائج التسليم الفعلية، ولا يحوّل نجاح البناء إلى تحقق من المزود.

## النطاق

قالبا KnowledgeGrid وServiceFlow فوق محرك واحد. المصادر نص أو TXT/Markdown بترميز UTF-8، حتى 12 KB لكل مصدر. التخزين خاص داخل PostgreSQL، مع chunks ثابتة متداخلة وGIN/tsvector باسترجاع `simple` للكلمات العربية والإنجليزية. هذا **lexical RAG** وليس embeddings أو بحثًا دلاليًا. لا PDF أو صور أو زحف URLs أو مزود embeddings جديد.

المصدر immutable بعد إضافته؛ التصحيح بإضافة مصدر جديد وحذف القديم. حذف المصدر يمحو محتواه وchunks، ويوقف التشغيل الجاري ويمنع إعادة استرجاعه حتى للإصدارات المنشورة. سجل الإجابات السابقة يظل مرئيًا لمالك المساحة كأثر تاريخي؛ لا يستخدم لإعادة الاسترجاع. الاستشهاد المقبول يطابق ID مقتطف حقيقي واقتباسًا حرفيًا منه. هذا يثبت أصل الاقتباس ولا يثبت صحة كل استنتاج للنموذج.

واجهة /studio و/ar/studio تضيف أقسام المعرفة والمحادثة والإعدادات والنشر والسجل. التشغيل يستخدم المسودة المحفوظة؛ المقارنة اختيارية وتشغّل نموذجي الإنتاج بالتزامن في طلبين مستقلين. لا استدعاء مزدوج تلقائي لكل رسالة.

[سجل النماذج الرسمي](https://console.groq.com/docs/models) بتاريخ 20 أكتوبر: الأولان Production والثالث Preview. أسماء المفاتيح لا تعني ثلاث حصص مستقلة؛ حدود Groq تخص المؤسسة. [المصدر](https://console.groq.com/docs/rate-limits).

`lib/studio/models.ts` يسجل قدرات موثقة وأسعارًا مؤرخة. التحقق من إتاحة الحساب منفصل. المخرجات JSON Schema strict مع تحقق خادمي للحقول والاقتباسات. لا نجمع structured outputs مع streaming أو tool use في طلب واحد، وفق [توثيق Groq](https://console.groq.com/docs/structured-outputs). دعم الصور الموثق لـQwen لا يعني قبول صور في المنتج؛ الواجهة نصية فقط.

طلب النموذج لا يشغّل SQL أو كودًا أو HTTP يحدده المستخدم. اقتراح طلب الدعم مخرج منظم يتحقق منه الخادم؛ الموافقة منفصلة ومربوطة بالسجل نفسه وبمالك المساحة. لا عرض أو حفظ للتفكير الخام. يسجل model، tokens، latency، request ID والتكلفة التقديرية ومصدر السعر. فشل المزود أو الصيغة لا ينتج إجابة ناجحة وهمية.

429: احترام Retry-After، محاولة واحدة إضافية فقط إذا الانتظار لا يتجاوز خمس ثوانٍ، ضمن مهلة التشغيل. لا تبديل مفاتيح أو نماذج للتحايل على الحصة. أخطاء الصلاحية والفوترة والنموذج والسعة منفصلة.

## التشغيل والعزل

RLS يربط القراءة بعضوية مستخدم ذي جلسة نشطة. تعديل المصادر والنشر والموافقة عبر RPC بعمليات محددة؛ دالة definer داخل schema خاص تتحقق من auth.uid والعضوية والجلسة. لا كتابة مباشرة للعميل على الإصدارات أو التشغيل أو المفاتيح أو الموافقات. وظائف إنشاء/إنهاء التشغيل وجلسات widget متاحة لـservice_role فقط، بعد تحقق الخادم من جلسة المالك أو credential محدود بالوكيل.

كل run محفوظ قبل الاتصال، وله snapshot وإصدار عند النشر وrequest key وinput hash. حد تزامن ذري للمساحة، مهلة محددة، طلب مزود واحد (مع retry محدود لـ429)، وإلغاء مراقب أثناء الطلب. لا عمل fire-and-forget بعد الرد. تنتهي leases المهجورة عند أول تشغيل تالٍ. إلغاء المصدر/النشر يمنع اعتماد نتيجة متأخرة. المقارنة لا تعطي أي نموذج صلاحية إضافية.

الإعدادات الخادمية الاختيارية: `AGYNEXA_RUN_CONCURRENCY` (افتراضي 6)، `AGYNEXA_RUN_TIMEOUT_MS` (45000)، `AGYNEXA_RUNS_PER_MINUTE` (60 لكل هوية)، `AGYNEXA_GLOBAL_RUNS_PER_MINUTE` (100). حدود إساءة وليست باقة مجانية أو سقف فاتورة. `AGYNEXA_STUDIO_ENABLED=false` يوقف Studio ومنافذ التشغيل الخارجية. التفعيل الافتراضي في هذا الإصدار مفوض بالنشر الكامل.

## النشر والاستخدام

Publish يثبّت التعليمات والنموذج وقائمة IDs المصادر في agent_versions غير قابلة للتعديل. تعديل المسودة لا يغيّر المنشور. Unpublish يوقف الاستدعاءات ويُلغي صلاحية جلسات widget القديمة، وإعادة النشر تولد generation جديدة.

API خادمي: مفتاح عشوائي 256-bit، مخزن كـSHA-256 فقط، مقيد بالوكيل، ينتهي بعد 90 يومًا وقابل للإلغاء. تظهر قيمته مرة في واجهة المالك، ولا تدخل snippet المتصفح. التدوير: أنشئ بديلًا، حدّث خادم المستهلك، ثم ألغِ القديم. إنشاء مفتاح جديد عملية صريحة؛ إذا ضاعت استجابة الإنشاء، ألغِ المفتاح من القائمة وأنشئ بديلًا.

widget داخل iframe بلا مفتاح API خاص. يصدر جلسة bearer قصيرة لعشر دقائق، مع حدود IP والوكيل. المعرفة العامة تعتمد صراحة عند إضافة المصدر وتُثبّت عند النشر. تعليمات المسودة الخاصة لا تُرسل إلى runtime العام؛ يستخدم تعليمات معرفة عامة ثابتة. لا صلاحية كتابة أو عرض سجل المحادثات أو المصادر الخاصة عبر widget. Origin ليس وسيلة المصادقة الوحيدة؛ الجلسة العشوائية وحالة النشر والتقييد العام مفحوصة في كل طلب.

ServiceFlow يقترح سجل دعم؛ عند الموافقة على الحقول المعروضة خلال 15 دقيقة يتحول إلى طلب داخلي معتمد مرة واحدة. لا Zendesk أو Salesforce أو رسالة بريد. القرار لا يقبل تعديل الحقول أو تغيير الطلب، ولا يسمح بقرار يناقض قرارًا سابقًا.

## البيانات والتراجع

المهاجرتان الجديدتان لهذا الإنتاج: أساس B `20261020102401_studio_foundation.sql` وC/D `20261020113246_studio_runtime.sql`. حالة التطبيق الفعلية تسجل في دليل الإصدار. لا إعادة لمهاجرتي الحسابات ولا نقل للموجزات أو تعديل إعدادات Auth.

التراجع المعتاد: تعطيل Studio أو إعادة إصدار التطبيق السابق مع الإبقاء على الجداول والبيانات الإضافية. لا DROP أو reset. قبل استعادة بيانات فعلية يجب تحديد نقطة الاستعادة والنسخة الاحتياطية المتاحة؛ نجاح rollback للكود لا يثبت اختبار استعادة قاعدة الإنتاج.

## E: حدود الاستعداد التجاري

النشر التقني لا يُقدَّم كجاهزية تجارية شاملة. استعادة الحساب ما زالت عائق إطلاق تجاري عام حتى اعتماد مسار أصلي من المزود أو بريد AGYNEXA مخصص. لم نغيّر Auth أو نفعّل SMTP أو OTP أو OAuth، ولم نرسل بريدًا. لا فوترة حقيقية أو تكاملات CRM/ERP أو ضمان SLA أو نتائج عملاء. القياس المضاف هو سجل التشغيل والاستهلاك، لا بوابة دفع.

التوثيق الذي يعلن B غير منشورة في تقارير A/B وصف تاريخي؛ إيصال هذا الإصدار هو المرجع الأحدث. فحوص التسليم مجمعة فقط وفق توجيه المالك، ولا تعاد بعد كل تعديل.
